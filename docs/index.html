How Stampwise
works.

Stampwise turns an incoming RFQ package for a pressure vessel into a reviewable quotation draft. This page explains what it reads, what it produces and where people stay in control.

1. Inputs

  • RFQ packages: specifications, data sheets, material requisitions, drawings and vendor forms.
  • Formats: PDF, Word and Excel. Drawings are read from PDF.
  • Languages: English and Korean, including mixed packages.
  • Your references: material price lists, fabrication rates and past quotations you choose to share.

2. How a package is processed

  1. Intake. Claude reads the full package with long context and builds an index of documents, sections and clauses.
  2. Requirement extraction. Each technical and commercial requirement is listed line by line with the source document and clause it came from.
  3. Gap check. Missing data, conflicting revisions and unusual conditions are flagged, with a draft clarification list for the customer.
  4. Workbook draft. The agent drafts a quotation workbook: materials, fabrication, NDE, testing and quantities. Every line keeps a link to its source.
  5. Engineering checks. Thickness and allowable stress checks for ASME Section VIII Division 1 and 2 run in deterministic code with source approved tables. The language model prepares inputs and explains results; it does not compute code values.
  6. Review and sign off. A named estimator reviews the draft. Nothing is priced or sent without human approval.

3. Outputs

  • Requirement list with source references.
  • Clarification list for the customer.
  • Quotation workbook in Excel, with traceable lines and review status.
  • Engineering check summary for the estimator and design engineer.

4. Architecture

  • Models: Claude through the Claude API. Development and operations use Claude Code.
  • Orchestration: agents built with the Claude Agent SDK.
  • Tools: Model Context Protocol (MCP) servers for pricing data, engineering tables and the calculation engine.
  • Traceability: a Neo4j ontology that links requirements, components, calculations and prices to their sources.
  • Gates: deterministic checks on quantities, totals and engineering values before any draft is marked ready for review.

5. Data handling

  • Customer documents are processed through the Claude API under Anthropic's commercial terms.
  • SPS does not use customer documents to train models.
  • Pilot documents are deleted within 30 days after the pilot ends unless you ask us to keep them.
  • See the Privacy Policy and Terms of Service for details.

6. Status

The agent has been in daily use on live bids at an ASME U stamp pressure vessel fabricator in Korea since early 2026. Pilot deployments for other fabricators and plant suppliers opened in October 2026. See Pricing.
